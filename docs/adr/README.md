# Architecture Decision Records

Architecture Decision Records document durable technical decisions that affect repository boundaries, interoperability, or long-term engineering policy.

## Format

Each ADR contains:

1. Context
2. Decision
3. Alternatives considered
4. Consequences

## Status vocabulary

- **Accepted** — the repository follows the decision.
- **Accepted — implementation pending** — the architectural direction is fixed, but the related product capability is not implemented yet.
- **Superseded** — a later ADR replaced the decision.
- **Rejected** — considered and intentionally not adopted.

ADRs must distinguish current implementation from future architecture.

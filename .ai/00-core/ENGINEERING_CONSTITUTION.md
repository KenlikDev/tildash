# Engineering Constitution

1. Correctness over convenience.
2. Preserve explicit behavior and invariants.
3. Prefer simple, explicit, maintainable code.
4. Avoid speculative abstractions and unnecessary dependencies.
5. Keep business rules independent from UI and infrastructure.
6. Make failures observable and actionable.
7. Treat security and privacy as design constraints.
8. Keep source code and developer documentation professional English.
9. Verify before claiming.
10. Never trade long-term correctness for a green local check.

AI assistance does not lower engineering standards.
